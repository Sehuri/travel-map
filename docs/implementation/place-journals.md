# 景点手记 v1：配置、权限与本地验证

本模块是独立地点档案与多篇到访手记，不写入城市足迹、公共五档景点评价或百城进度。没有生产种子数据。原型中的标题、评分和篇数未录入。

## 当前交付与上线前置

仓库内已准备前端、SQL、私有图片读取函数和本地测试。2026-11-10 站主反馈已完成线上配置；只读检查确认公开列表接口返回 200、匿名草稿读取被拒绝、图片函数 OPTIONS 返回 204。以上连通性检查不代表完整的发布及图片权限验收，后续结果见验证记录。

新环境部署时，需在获得明确授权后执行：

1. 确认项目已有 `schema.sql` 中配置好的 `public.is_current_user_owner()`，以及 `admin_backend.sql`、`journeys.sql`、`attraction_ratings.sql` 的表。
2. 审查并执行 `supabase/place_journals.sql`（与 `supabase/migrations/20261109000000_place_journals.sql` 一致），按项目现有迁移方式运行其一，不重复创建另一套表。
3. 确认 `place-journal-media` 桶为 **private**。迁移只为本模块新增桶及受限策略；若同名桶已是公开，迁移会失败并回滚，避免把旧资料意外改成其他权限。
4. 审查 `storage.objects` 上是否有其他不限定桶、允许所有用户读取的宽泛策略。PostgreSQL 的宽松策略会相互 OR；新增限制策略无法抵消其他宽泛授权。本仓库已有城市相册策略限定在原桶，不需要修改。
5. 部署只读 `journal-media` Edge Function，按 `supabase/config.toml` 的 `verify_jwt = false` 配置。参考命令（本次未执行）：`supabase functions deploy journal-media --no-verify-jwt`。
6. 函数读取服务器环境 `SUPABASE_URL` 与 **普通 anon JWT** `SUPABASE_ANON_KEY`，不使用 service_role。主人请求转发其用户 JWT，游客使用 anon 身份，数据库及存储 RLS 在每次读取时重新检查。若项目禁用了 legacy anon JWT，应先确认函数可用的普通匿名凭据；不要换成管理员密钥绕过 RLS。
7. 在 Supabase Auth 的允许跳转地址中加入实际编辑页，例如 `https://sehuri.github.io/travel-map/journal-edit.html`。本地邮箱登录测试需另允许具体 localhost 地址。本次未修改 Auth 配置。
8. 用真实站主、匿名、登录非主人执行部署后的端到端复核，再决定发布前端。

前端继续使用已有 `assets/supabase-config.js` 的公开 URL / publishable key。不会将服务器密钥发到浏览器。未配置时页面提示服务不可用并允许重试，不显示原型数据或虚假保存成功。

## 页面与数据

- `journals.html`：公开列表；`?view=mine` 是主人自己的记录，分别筛选状态与可见性。所有条件写入 URL，详情返回验证为同源同列表路径。
- `journal.html?id=<uuid>`：按授权版本读取，私密/草稿/不存在的记录对访客均显示不可用。
- `journal-edit.html?id=<uuid>`：编辑这一篇；`?place=<uuid>` 为同一地点新写一篇；`?journey=<slug>` 可预填已有旅程。
- `journal_places`：稳定 UUID 的地点档案。国家、位置、类型、坐标、已有城市名、旧目录 ID 可选，城市继续复用现有按名称标识的口径。目录 ID 有外键，不以名称跨地区去重。
- 选其他已有地点后只读；如需不同资料，显式“复制地点资料并修改”，不覆盖其他手记。新建地点仅被本篇草稿引用、且尚无发布版本时（包括重新打开这篇草稿），可继续补全位置等信息并保持同一 ID；一旦被其他手记或发布版本引用，数据库也会拒绝隐式改写，必须明确复制。
- `journal_entries`：手记身份、状态、当前发布版本与乐观锁 revision。
- `journal_drafts`：私有内容及期望可见性；草稿选择公开仍不会公开。
- `journal_versions`：不可直接更新的已发布快照。发布 RPC 原子切换指针，旧版不再对访客可见。
- `journal_media`：仅存媒体资源与父手记，内容快照按稳定媒体 ID 引用、排序和指定封面。

公开列表通过 `journal_public_entries` 受限投影视图读取，只给出“已发布+公开”的条目，且不会把私有修订的更新时间/revision 泄露给访客。其他关系表也有行级策略；搜索、筛选、计数只作用于当前已授权结果。旅程入口由读取函数审查，未公开旅程不会给游客返回标题/链接。已有内置公开旅程继续按 slug 引用。

## 照片、隐私及失败恢复

- 新上传走私有桶，不依赖是否关联城市。复用当前项目的文件校验和 JPEG/PNG 预览生成器；其他支持格式经浏览器解码重绘。
- 支持 JPEG/PNG/WebP/GIF/AVIF，输入每张 15 MB，单篇最多 100 张。浏览器不能解码时保留队列、显示失败并允许重试。HEIC/HEIF 未支持转换，会立即提示先导出 JPEG。
- 手记新媒体存储最大宽度 1600px 的 WebP 和 480px 缩略图，不保存新原文件；重绘去除 EXIF，包括 GPS。动画格式变为静态图。现有城市相册原图和上传流程不改变。
- 新资源先注册在父手记下，上传成功且两个对象均存在才标记 ready。只有 ready 且被当前公开版本引用的图片可被访客读取。失败对象/未引用资源留在私有桶，不会因猜到地址而公开。
- `journal-media` 只读代理不生成签名 URL，返回 `Cache-Control: private, no-store`。撤下公开后，后续读取按新的权限拒绝；曾被公开查看或下载的内容无法追溯收回。
- 不允许覆盖或删除已上传对象。更换图片会创建新资源，移除仅删除本篇引用；不会删除共享原图。失败资源暂不自动清理，可在后续授权下审查清理。
- 已有公开相册引用保持原公开属性，选择器与发布侧栏明确提示。不能承诺“把原本公开的照片变私密”。
- 单张失败可单独重试，其他已上传照片不会重传或清空。保存失败保留文字和队列；有未保存修改/未上传文件时离开会触发浏览器提醒。没有自动保存。

## 发布规则

保存草稿只要求地点名。发布还需要位置文字，以及已上传照片或非空感受。日期与整数评分可空，不用 0 分替代未评分。标题空时生成“地点名 · 日期”并在确认面板供主人确认；可以取消返回修改。

已发布条目编辑只写私有草稿，原公开快照与图片继续原样显示。点击更新发布才切换版本。撤下公开立即把已发布条目设为 private；归档保留内容与资源，可以恢复为草稿。乐观锁冲突会提示重新打开，拒绝覆盖另一个编辑窗口的更新。

## 测试入口及验证边界

- `npm run test:unit`：包括本模块内容/筛选、真实 PGlite PostgreSQL RLS、图片函数测试。
- `npm run test:journals`：本地 HTTP + 浏览器 + 真实临时 PostgreSQL，使用隔离的 SDK/存储适配器，不连接生产写接口。
- 如测试自带 Chrome 不存在，可设 `CHROME_PATH` 为本机 Chrome 可执行路径。
- 手记浏览器测试默认截图写入 `/tmp/travel-journals-qa`；可用 `TRAVEL_QA_DIR` 指定位置。

本地 SQL 策略测试与浏览器适配器不是线上 Supabase 网关、JWT 配置或真实 Storage HTTP 的验收替代。部署后仍须使用真实身份检查匿名/非主人对列表、详情、地点、修订、媒体、直接对象地址及旧版本的访问；验证撤下公开之后新的图片请求失败。
