日期：2026-10-15。范围：discover.html 的视觉与交互设计，不改业务代码。

这是沿用已选定白蓝首页风格的一套连续流程，不是三个互斥方向。三张为静态交互状态图，不可直接点击，不代表页面已完成开发。

## 视觉原则

- 白底 #FFFFFF，浅灰蓝 #F5F8FC，主蓝 #3268E8，正文 #233244，辅助文字 #65758C。开发仍需测量可访问性对比度。
- 复用首页字体、导航、图标、圆角和控件规范。中文采用无衬线字体；正文约 15–16px；主操作至少 44px 高。
- 不保留照片壁纸、大块半透明绿色背景、荧光黄色和大面积衬线标题。
- 表单和统计按留白、对齐、细线组织；独立候选可用细边框，候选内各指标不再各套一个盒子。
- 地图分类可保留绿色景点、橙色用餐候选；蓝色仍是全站操作色。类别同时使用文字、编号等信息，不只靠颜色。
- 纸飞机与山形为轻装饰示意，可省略；如保留应使用实际素材或现有图标，不阻塞核心功能。
- 不要求迁移 React，不为换外观引入多套组件库，继续复用现有 Heroicons。

## 核心流程

填写条件 → 抽取并核验交通 → 比较候选 → 展开目的地资源 → 生成每日攻略 → 保存或复制。

修改条件返回表单；返回候选恢复同一批候选；换一组才重新抽取。这些导航只整理现有页面状态，不强制新增路由、数据库或后端接口。

## 状态与操作规范

| 场景/操作 | 预期交互 |
| --- | --- |
| 连接城市目录 | 紧凑状态行显示连接中，出发地与抽取按钮暂不可用；不要用巨型提示卡片挤掉表单 |
| 连接成功 | 展示真实城市数量和更新时间；覆盖说明可展开，明确实际覆盖范围，不暗示目录完整覆盖所有地区 |
| 连接失败 | 显示失败原因、重新连接、体验现有18城示例；示例状态在候选与详情保持可见，不能冒充全国模式 |
| 出发地搜索 | 必须选择完整行政归属并绑定真实城市ID；重名城市和县级市不可仅按名称判断；未选完整时字段旁报错 |
| 游玩天数 | 1–14整数，不含往返交通；步进器与输入值同步，越界、非整数要明确提示 |
| 兴趣多选 | 最多3项、任一匹配；不选则随缘。计数和摘要同步，第四项不能悄悄替换既有选择 |
| 更多条件 | 可折叠目的地省份、旅行节奏、排除已去过城市；折叠不清空其值，数量基于已有逻辑 |
| 右侧摘要 | 由表单实时派生，不维护一份容易过期的独立数据；标签可移除时必须同步原控件 |
| 抽取 | 主按钮切换加载态，防重复提交；显示真实阶段文字，不造假百分比；保留输入值 |
| 无候选/少于3个 | 不自动放宽条件；说明可扩大距离/预算或修改省份；只有1–2个时据实显示数量，不补造城市 |
| 候选卡片 | 指标顺序一致，保留行政归属、直线距离、交通、预算、季节说明与数据来源 |
| 交通估算/接口规划 | 各交通方式分别标注来源。接口暂不可用可用既有估算，但不能把全局“高德规划”提示与卡片“估算”混用 |
| 修改条件 | 回表单并保留输入；不重新抽取。发生修改后旧候选标为旧条件结果，需明确重新生成，不能把旧数据解释为新条件 |
| 换一组 | 用当前有效条件重新抽取，保留已有去重与seen规则；不要固定抽中原型中的三个城市 |
| 选择目的地 | 仅获取所选城市资源，显示加载与重试；失败时保留候选方便改选，不留半完成页面 |
| 返回候选 | 恢复当前批次快照与条件，不悄悄重新随机；返回后焦点落在此前选择的候选入口 |
| 资源总览 | 分类筛选全部/景点/美食，编号对应列表；点击资源有定位和详情反馈，外链保留安全属性 |
| 生成攻略 | 初次显示“一键生成N天攻略”；生成后进入每日攻略，后续显示重新生成。基于现有算法，不冒充AI已核验行程 |
| 全部/第N天 | 全部展示全部日程点位和分日顺序线；某一天仅展示当天点位。地图与攻略始终同步 |
| 分类与日期切换 | 明确哪个模式控制地图。切回资源浏览后取消日期选中/显示资源模式提示，不让“只看美食”和“第1天”出现互相矛盾的激活态 |
| 保存愿望清单 | 复用已有保存逻辑和去重；成功后变为已保存并反馈，失败可重试，不宣称云端同步 |
| 复制 | 区分旅行灵感和每日攻略；只在用户点击时复制，反馈成功/失败，权限拒绝时可手动选择文本 |
| 地图失败 | 保留资源列表和攻略，显示重试/外部地图入口，不能让整页结果消失 |

新增的进度条主要用于表达状态。尚未到达的步骤不可用；不是必须实现的复杂向导或三个新页面。

## 手机与中屏规则

本轮未单独生成手机图，以下是开发要求，不声称已有移动端视觉验证。

- 桌面表单+摘要左右布局；中屏合理换行；手机改一列，摘要放到字段后方，可用紧凑底部抽取栏，但不要遮挡最后字段和错误提示。
- 兴趣标签自然换行，不让小字强行塞一行。保留明确的最多3项说明。
- 三候选手机纵向排列，数据顺序一致；不要做必须横向滑动才能比较的宽表格。
- 目的地页手机先概要与地图，再日期和攻略；日期可横向滚动但必须有清楚选中态。地图高度约280–340px，不挤满整屏。
- 导航继承首页已有手机规则，“返回地图”入口可见。键盘弹出时表单与底部按钮可用。
- 检查390px手机、768px中屏、1024px平板及1440px桌面，无横向溢出，并保留键盘焦点和减少动画偏好。

## 数据真实性与图中示意

1. 719城市、48排除城市是2026-10-15本次浏览快照，不写死，也不代表完整全国统计。
2. 青州市、丽水市、宁乡市及交通、预算，是现有页面的一次抽取结果，交通实际处于距离估算降级。不是本次调研核验的实际班次、费用或建议目的地。
3. 本次实际浏览未勾选兴趣。原型图的“山水自然+历史人文”是展示多选交互的示例，不代表实际抽取结果已按这两个偏好重新检验。开发必须由真实条件驱动摘要与结果。
4. 图中地图、地名、道路、标记、比例尺与地图版权文字均是生成示意，不能裁切使用或复制审批编号；使用真实地图SDK及其来源署名。
5. 丽水第1天样例为本次已有算法输出：缙云仙都景区 → 缙云烧饼总部（用餐候选）→ 朱潭山，点位间直线合计约2.3km。此为草案，不代表已核验开放时间、预约、营业、实际路程或用餐适宜性。
6. 资源点位是线索，不是推荐品质排名。不要新增“最佳城市”“可信度98%”等现有逻辑不支持的文案。
7. 三图没有展示完整资源列表、失败态、全部候选数量和全部日期等状态；不等于删除这些能力。图内轻微字形、图标和间距误差以设计规则和真实组件为准。
8. 本轮发现旧版结果提示会概括写“交通来自高德路线规划”，但卡片是估算；后续开发应让总体提示与各方式实际来源一致，不需要为此重写估算算法。
