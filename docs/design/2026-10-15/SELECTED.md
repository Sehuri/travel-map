## 固定的设计方向

保留实拍背景、深蓝青绿、荧光绿重点色和中文衬线标题。缩短首屏，使地图成为紧接首屏的主要内容；把城市筛选放在地图旁。精选旅程承接地图浏览，照片与故事继续提供个人特色。

桌面结构：

1. 紧凑导航：品牌、地图、旅程、影像、数据、下一站。管理入口降低视觉权重，窄屏时切换菜单，避免汉字竖排。
2. 短实拍首屏：适度的两行标题「世界很大，我用足迹丈量。」、动态城市/国家/旅程数字、主按钮「探索我的地图」与次要入口「最新旅程」。正文对照片的遮罩足够稳定。
3. 地图分区：标题、城市搜索、年份、国家/地区与三种地图范围切换靠近摆放。地图是可操作的现有地图，不是原型图片。
4. 精选旅程：真实封面、最多两行标题、日期和简要统计，提供查看全部入口。首页通常展示 3—4 趟以内。
5. 后续内容：紧凑照片放映预览、今日回忆、近期足迹、数据摘要。完整历史与相册通过展开或已有入口继续浏览，避免默认全部铺开。

手机地图结构：

1. 紧凑标题与菜单，随后是城市搜索和一行常用筛选。
2. 大面积可操作地图，保留缩放与地图范围入口；当前选择城市应在可见范围内。
3. 选中城市底部卡：真实缩略图、城市名、当前到访日期、照片数和「查看城市记忆」。可收起或进入完整详情。
4. 城市卡下方是四项导航：地图、旅程、影像、愿望。为卡片、键盘和底部导航分别留出空间。
5. 无音源时不展示固定音乐条；有音源时用小按钮，不能遮住表单、地图控件或主要操作。

手机图展示的是进入地图并选中城市后的状态，不表示手机打开首页时要自动跳过首页或自动选中新加坡。

## 实现尺寸起点

| 项目 | 起点 |
| --- | --- |
| 桌面内容最大宽度 | 约 1200—1320px，页面居中 |
| 桌面导航高度 | 约 64—72px |
| 桌面首屏照片区域 | 约 320—420px，随内容自适应，不强制占满一屏 |
| 桌面地图高度 | 约 480—600px，可全屏；不为实现图片比例而挤压控件 |
| 手机地图 | 地图主题内优先获得屏幕空间，按视口与安全区域计算可用高度 |
| 手机城市卡 | 收起状态约 150—220px，内容变多时可展开；底部导航单独占位 |
| 正文字号 | 约 16px；辅助文字尽量不小于 13px |
| 主标题字号 | 桌面约 56—72px，手机约 36—44px，需实际检查换行 |
| 主交互目标 | 约 44px 及以上，键盘焦点清楚 |
| 响应式复核宽度 | 390、768、840、1024、1440px |

这些尺寸用于帮助实现，不是原型图的逐像素测量。优先保证真实中文长标题、输入框、地图控件和动态数据的可读性。

## 本轮必须保留的行为

- 原生 HTML/CSS/JavaScript、Supabase、GitHub Pages、高德/Leaflet、WGS-84/GCJ-02 处理继续沿用。
- 现有随机实拍背景机制继续沿用：每次进入选择一张，本次浏览不自动轮播，固定背景；不是把背景永久改为鱼尾狮一张照片。
- 城市与时间线共享筛选逻辑；支持清除、无结果、加载和地图降级。
- 城市详情、重复到访、`?city=...` 与 `visit=...` 链接、分享和攻略入口保留。
- 正式旅程、路线回放、照片墙/放映、愿望、随机推荐、评分、管理仍可到达。
- 手机历史年份默认仅展开最近一个有记录的年份，其他年份可展开查看。

详细交互、页面入口和验收要求继续以同目录 `README.md` 为准。

## 原型图的数据纠正

图 1 中最新旅程卡片的部分统计和日本旅程日期有生成偏差。开发时从现有数据读取：

- 新加坡与印尼国庆之旅：2026-10-01 至 2026-10-07，7 天，5 座城市；本轮审查时关联 33 张旅程照片。
- 日本旅程：2026-02-03 至 2026-02-12，10 天；不使用图中的 2025 年日期。
- 本轮审查时总计 57 城市、4 国家、70 次到访、9 份旅程、131 张照片；这些数值不硬编码，以当前真实记录与后台为准。
- 图片里的地图位置、边界、地名和部分小图只是示意。使用现有地图与真实照片，不从原型裁出底图或旅游照片。
- 手机原型的「2026」「新加坡」是示例状态；实际初始筛选和选中项由产品逻辑决定，不强制写死。
