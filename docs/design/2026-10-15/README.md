## 图片中必须纠正的示意内容

生成图不是数据库，也不是正式地图。开发前读取当前仓库和后台返回值，动态渲染统计、日期、城市、图片、评分与路线。

1. 图 1 下方两张旅程卡片中的日期、城市数、照片数有生成偏差，不照抄。新加坡与印尼旅程日期为 2026-10-01 至 2026-10-07，7 天、5 座城市；本轮线上审查时关联 33 张旅程照片。日本旅程为 2026-02-03 至 2026-02-12，10 天，不能使用图中的 2025 年日期。
2. 图 3 手机路线中的地图编号存在重复与错位，不照抄。真实站点依次为：01 南京、02 新加坡、03 雅加达、04 泗水、05 雅加达、06 广州、07 南京。重复城市是独立停留站，不能按城市名去重。
3. 所有图的地图边界、地名、城市点、连线和标注只示意布局。继续使用项目现有高德/Leaflet 地图、坐标转换及路线数据，保留地图提供方原有标识；不得将生成地图作为正式底图或行政区数据。
4. 图中东京、京都等小幅照片有示意生成内容。实际开发复用项目与后台真实照片，不把生成图裁切成“用户实拍”。没有照片时使用明确的无图样式。
5. 截至本轮审查，线上显示 57 城市、4 国家、70 次到访、9 份旅程、131 张照片。数字仅用于核对，必须动态计算，不能写死。年份筛选项也从数据产生，不能照图固定为 2026。
6. 图中部分图标与字体细节仅是示意，使用项目现有资源或一致的图标库实现。正文、按钮、表单、地图都需要是真实可操作元素。

## 共同目标

让访客快速找到地图和最新旅程；在地图附近完成筛选；在手机上查看城市时不被固定浮层遮挡；保留个人照片与旅行档案的气质。

已有功能应有明确入口：全球/省级/中国细节地图、城市时间线、重复到访、旅程档案、路线回放、照片墙及放映室、往年今日、统计、评分排行、愿望清单、随机旅行、攻略与站主管理。

保持现有原生 HTML/CSS/JavaScript、Supabase 与 GitHub Pages 架构。此次是前端改版，不要求换框架、迁移数据库或重写后台。

## 页面结构与导航

### 公共桌面导航

建议显示五个清楚的主题：地图、旅程、影像、数据、下一站。管理入口收进低权重菜单。

| 导航 | 默认使用现有入口 | 补充入口 |
| --- | --- | --- |
| 地图 | `#map-section` | 时间线可作为同主题的列表浏览方式 |
| 旅程 | `#journey-archive` | 每趟仍进入现有 `journey.html?slug=...` |
| 影像 | `#photo-cinema` | 照片墙、按城市/旅程选择、放映 |
| 数据 | `#journey-stats` | 排行放入数据主题，保留原有锚点兼容性 |
| 下一站 | 现有愿望面板 | 内部提供“我的愿望”和“随机旅行”两个明确入口 |

不要求为了导航新增五套页面。可先复用现有锚点、面板和链接，滚动时给当前位置提示，并提供容易到达的主题切换入口。

手机采用四项底部导航：地图、旅程、影像、愿望；数据、随机推荐、站主管理由菜单或主题内入口访问。音乐不占用独立固定条：无音源时隐藏；有音源时使用不会遮住内容的小按钮。

### 首页内容范围

已选用方案 1：首页短首屏 → 地图与筛选 → 精选旅程 → 放映预览 → 紧凑今日回忆 → 近期足迹 → 数据摘要。原型图重点画出首屏、地图、最新旅程和手机城市卡，其余模块依照同一规范紧凑呈现。

方案 2：地图工作区优先，城市列表和地图在同一视野；完整旅程、影像和数据通过清楚的导航访问。不要把后面的所有模块继续堆到地图下面形成超长页。

方案 3：简短个人介绍 → 最新精选旅程 → 本次旅程的城市节点 → 地图入口；完整旅程的路线回放继续使用现有详情页。

所有方案：首页精选旅程通常不超过 3—4 趟，首页排行不超过 5 条。历史年份可折叠，手机默认展开最近一个有记录的年份；其他年份显示年份与到访数。照片墙仍可查看全部照片，首页只提供预览。

## 关键交互规范

### 地图筛选

搜索、年份、国家/地区在地图区域内可直接操作。桌面采用就近工具栏，方案 2 可置于侧栏；手机搜索置顶，次要筛选放折叠面板或底部选择面板。

使用同一份筛选状态驱动现有地图与时间线，保留项目已有联动逻辑。展示已应用条件、匹配城市数和“清除筛选”。处理无结果、加载中和地图失败状态。切换地图范围不应意外丢失筛选。

保留海外可见性、城市名称与经纬度的现有来源。选中新加坡等海外城市后自动调整地图视野，不把它留在可视区之外。

### 选中城市

桌面：点击地图点或侧栏城市 → 显示对应城市预览、更新地图选中状态 → 点击“查看城市记忆”打开原有完整城市详情。

手机：点击城市 → 地图保留在后方、选中点可见 → 底部城市卡展示城市名、到访日期、封面和照片数量 → 可以展开、关闭，或进入完整详情。底部卡放在底部导航之上，控制高度；键盘打开时输入框和操作按钮保持可见。

若有重复到访，预览应明确当前日期，并提供全部到访入口；城市记录不能被一次预览覆盖。保留 `?city=...`、`visit=...` 以及复制/分享链接能力。

完整详情采用清楚的概览、照片、到访/旅程、攻略分区。没有攻略与个人建议时，对访客收起空分区；站主仍有可达的编辑入口。手机可使用全屏详情，关闭/返回操作始终可达。

### 旅程与路线

精选旅程卡片：真实封面、标题、日期、天数、城市数，以及明确详情入口。标题最多两行，摘要最多两行，复杂路线在详情中完整展示。

旅程详情：顶部展示准确日期与紧凑概览，提供概览、路线、照片、游记、攻略的页内导航。路线回放复用现有引擎，保留播放/暂停、前后站、站点点击、交通方式和分享链接。

方案 3 的手机路线中，当前站卡、进度、站点照片和地图标记同步。01 南京和 07 南京、03 雅加达和 05 雅加达分别是不同站点。

### 数据与加载

当前“累计旅行天数”显示首次足迹至今的跨度，前端应改成“距离第一次旅行”或“旅行记录跨度”。不要仅改样式后继续使用误导标题，也不要未经确认推断真实在途天数。

加载期间采用稳定占位与短状态文案，避免先展示 0 城市、0 国家和 0 照片再突然跳变。已连接提示保持简短；故障时显示原因与恢复入口。地图服务不可用时保留列表或现有地图降级方式。

## 视觉与响应式规格

以下数值是实现起点，不是对生成图片逐像素测量的结论。

| 项目 | 建议 |
| --- | --- |
| 主色 | 深蓝 `#07111f`，青绿 `#12373d`，米白 `#eef3ea`，重点色 `#e4ff75` |
| 字体 | 沿用中文衬线标题与无衬线正文；正文约 16px，辅助信息尽量不小于 13px |
| 主标题 | 桌面约 56—72px，手机约 36—44px；长旅程标题按容器缩小或换行 |
| 分区标题 | 桌面约 32—40px，手机约 26—30px |
| 页面宽度 | 桌面主要内容约 1200—1320px；地图工作区可更宽 |
| 页面间距 | 采用 8px 基础刻度，常用 16、24、32、48；减少无内容的大块留白 |
| 桌面导航 | 高约 64—72px，文字约 14px，禁止汉字挤压成竖排 |
| 紧凑导航 | 约 1100px 以下逐步切换紧凑菜单，按实际内容校准 |
| 手机布局 | 767px 以下单列/抽屉布局；按安全区域处理底部导航与城市卡 |
| 控件 | 主要交互目标约 44px 及以上；焦点清楚；选中状态含文字或形状提示 |
| 图片 | 保持原比例，明确封面裁切焦点；缩略图与大图分别处理，不把背景图拉伸 |
| 内容表面 | 保持实拍氛围，密集文字使用足够稳定的底色，减少叠加磨砂和阴影 |

默认沿用现有每次进入选择一张背景、同次浏览不自动轮播的机制。原型显示的单张照片与遮罩仅是此机制的一种呈现。不要据此移除用户原来的照片选择或固定背景行为。

## 验收重点

1. 按已选用方案 1 实现，首轮重点是首页、导航、地图筛选和手机城市卡，视觉对照 `01-prototype.png`。
2. 在 390、768、840、1024、1440px 等宽度核对，尤其是导航换行、长标题、侧栏、表单和底部浮层。
3. 地图三种范围、城市搜索、年份/地区筛选、清除、无结果和服务失败均可操作。
4. 城市详情、重复到访、分享深链接、真实照片、旅程详情和路线切站不回退。
5. 首页缩短后，历史年份、完整相册、全部旅程、愿望、评分与管理入口仍可到达。
6. 输入框、按钮、关闭/返回和地图缩放不被音乐、城市卡或底部导航遮住。核对键盘操作、焦点、减少动态效果和手机安全区域。
7. 根据改动运行项目现有相关测试，并用浏览器复核桌面与手机截图；如旧测试依赖被调整的 DOM，按实际业务行为更新测试。
8. 数据来自当前真实记录，不照抄生成图中的日期、图片、标记和数字。截图对比可以验证布局，无法代替交互验证。
