# 手记选图与发布反馈修复

## 原因

相册打开操作结束后，`setBusy(false)` 通过 `setPlace()` 把尚未保存的地点输入覆盖为初始模型值。第一次填写后直接打开相册时，地点名称会被清空；随后选图和发布均被必填校验阻止。选图失败提示又位于弹窗背后的页顶，发布校验提示也位于页顶，滚动到操作区时难以察觉。

已先补充回归步骤并复现失败：打开相册后，地点名实际为 `''`，预期为未保存的输入。修复后解锁仅改变控件可用状态，不回填字段；地点资料回填只发生在明确的选择/复制操作和初次加载。

## 修复内容

- 打开/关闭相册、加载失败和操作解锁均保留未保存的地点资料。
- 发布操作区增加就地状态与错误提示；相册和发布确认框显示各自进度、失败原因并允许重试。
- 相册明确显示“点击添加”，处理期间阻止重复操作；重试不会重复加入已有照片引用。
- 保留草稿/发布权限、发布前确认、现有照片和城市统计规则，未修改数据库、存储或权限。

## 实际验证

- 93 项单元测试通过。
- 完整手记浏览器流程通过，运行真实临时 PostgreSQL/RLS 与隔离存储适配器；新增覆盖未保存字段、发布校验可见性、相册保存失败后单张重试，以及发布失败后在原确认框重试成功。
- 390/768/1024/1440px 原有响应式检查通过；新增相册错误在 390px 与 1440px 截图并实际查看，发布确认错误截图已查看。
- 真实站主页面已恢复被清空的地点名/国家并成功保存草稿，发布确认能打开；没有点击最终确认发布。
- 此记录生成时，最终修复代码仍待推送部署；真实线上相册添加与新版本反馈仍待上线复核。本地隔离测试不等于生产图片网关与完整公开发布的验收。
