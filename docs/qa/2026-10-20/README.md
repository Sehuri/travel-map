# 后台照片拖入与待上传列表

## 使用

登录后台 → “照片与封面” → 选择城市 → 从 Mac“照片 App”的照片缩略图或访达拖入虚线区域，或点击“从相册 / 文件选择”。可以分批追加，查看缩略图，单独移除或清空，最后点击“上传照片”。拖入本身不会上传；刷新/离开页面会清空本地待上传列表。

文件仍由原有站主身份上传，继续使用自行生成预览图的流程。没有新增第三方服务、数据库迁移或权限变更。不同照片即使同名，也不会误当作重复；重复检测按内容进行，仅在当前待上传列表内生效，不是全站照片去重。

支持 JPEG/PNG/WebP/GIF/AVIF，单张不超过 15 MB。空文件、未能下载的 iCloud 占位、HEIC/HEIF 与其他格式会被拦截并提示。HEIC/HEIF 请先从“照片”导出为 JPEG，不会偷偷压缩或转换原图。文件名含中文或系统导出未提供 MIME 时，沿用安全 ASCII 存储路径及原有格式推断。

上传时锁定城市与待上传列表，防止途中换城市或移除文件；每张成功写入数据库后才移出列表，中断后未完成项保留，可继续上传，已完成项不会重复提交。

## 验证边界

- 完整 `npm test`：81 项单元测试、8 组浏览器测试通过；视觉微调后再次执行照片拖拽专项测试通过。脚本语法与 `git diff --check` 通过。
- 本地模拟站主与存储，不调用真实 Supabase 写接口，不读取或修改系统照片图库。
- 浏览器拖拽测试使用标准 `DataTransfer` 文件，覆盖多选、追加、同名不同内容、重复跳过、取消、移除/清空、格式/大小/占位检查、链接不下载、上传锁定、部分成功后的重试以及 1440px / 390px 布局。
- **未实际从 Mac“照片 App”拖到 Safari / Chrome 实机确认**，也未做 iPhone 真机测试。如果系统只交给网页相册链接或空数据，界面会明确提示，而不会自动抓取链接；可先下载 iCloud 原片，或导出 JPEG 再拖入。
- 新增单元测试检查格式边界和同步读取 `FileList` / `DataTransferItem`。文件只在 `drop` 事件中读取，符合 [MDN 拖拽文件说明](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files)。
