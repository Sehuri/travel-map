# 照片预览优化

## 数据与原图保护

2026-10-19 从当前公开照片表读取 751 条可见记录，与项目内置照片合并去重，共 777 个原图 URL。全部成功生成预览，无失败或动画跳过项。原图只读入内存处理，没有覆盖原文件，没有数据库、权限或线上存储配置变更，也没有实际测试上传到线上。

原图合计约 2.03 GB；这是文件体积统计，不是首页一次性下载量。各档按同一批图片比较：

| 用途 | 目标宽度（不放大小图） | 合计大小 | 比原图减少 |
| --- | --- | --- | --- |
| 城市小图 / 放映缩略图 | 480px | 30.4 MB | 98.50% |
| 常规列表 / 封面 | 960px | 119.3 MB | 94.13% |
| 大幅封面 / 放映画面 | 1600px | 273.1 MB | 86.56% |

某些原图较小，后两档会复用同一个预览，以上各行不能相加作为实际新增空间。实际新增预览文件约 400 MiB，作为静态资源随网站发布；首次推送比仅修改代码耗时更长。后续后台新上传预览直接存原 bucket，不需要每次重新构建静态资源。

详细机器记录：[photo-performance.json](./photo-performance.json)。实际加载时间取决于网络与缓存，未把文件体积降幅当作页面提速倍数。

## 实现范围

- 城市详情相册、城市地图预览、最近到访与时间线、旅程封面与相册、后台照片选择器接入统一预览加载。
- 响应式 `srcset` / `sizes`、已知图片宽高、延迟加载与异步解码；预览失败回退原图，原图也失败才进入不可用状态。
- 放大查看仍使用原图。放映室可见后才初始化图片，播放时才预取下一帧，省流量模式不预取。
- 新 JPEG / PNG 上传在浏览器自行生成预览，全部上传成功才标记可用；编码/存储失败不丢失原图并提示。GIF/WebP/AVIF 等新上传维持原文件，静态图可用批量脚本补齐，避免误把动画压成静帧。
- 本地生成使用内容哈希文件名；新上传使用随机唯一文件名与长期缓存。无需新数据库列或付费缩图服务。
